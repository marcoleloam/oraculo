# Nomes dos projetos nas pastas do Obsidian

`oraculo obsidian project-labels` gera um snippet CSS que acrescenta o nome antes
do identificador no explorador de arquivos: `Projeto Á — <UUID>`. O texto original
do UUID continua no elemento. Caminhos, IDs, notas, links e isolamento da memória
continuam canônicos. Não há migração, plugin ou mudança do daemon.

O comando é offline: lê somente o JSON fornecido e escreve CSS em stdout. Não
carrega a configuração nem abre vault, SQLite ou conexão com o serviço. A instalação
do snippet é uma etapa explícita no Obsidian. A seleção por `--project` é obrigatória
e pode ser repetida; não existe seleção implícita de todos os clientes.

## Gerar a partir de metadados reais

Na release que contém este comando (ou com `uv run --frozen oraculo` no checkout),
obtenha um snapshot pelo serviço suportado e gere um artefato fora do vault:

```bash
labels_dir="$(mktemp -d)"
oraculo status > "$labels_dir/status.json" &&
oraculo obsidian project-labels --file "$labels_dir/status.json" \
  --project PROJECT_ID_A --project PROJECT_ID_B > "$labels_dir/project-labels.css"
```

Substitua os IDs pelos retornados em `status`. O serviço atual guarda `id`, `path`
e `status`; nesse formato o nome é o último componente de `path`. Não se consulta
o diretório de trabalho do projeto. O caminho absoluto não aparece no CSS.

Para usar os títulos exibidos pelo T3, exporte a resposta estruturada de
`t3_project_list` pelas ferramentas oficiais do host. Reúna todas as páginas
(`nextCursor` não nulo é recusado), mantendo somente os metadados necessários:

```json
{
  "projects": [
    {"id": "PROJECT_ID_A", "title": "Projeto Á"},
    {"id": "PROJECT_ID_B", "title": "Outro projeto"}
  ],
  "nextCursor": null
}
```

Os nomes acima são exemplos; use os títulos reais. Passe esse arquivo em `--file`
em lugar do status. Também é possível receber JSON por stdin. `title` tem
precedência sobre `path`; nomes e IDs não são deduzidos do conteúdo da memória.
IDs desconhecidos, metadados ambíguos, projetos removidos e colisões de caminhos
falham sem emitir CSS parcial. Nomes iguais em projetos diferentes são permitidos:
os identificadores continuam distintos. IDs como `mcp:...` usam a mesma chave
`p-<sha256>` do publicador existente.

## Instalar e ativar

O Obsidian oferece [snippets CSS](https://help.obsidian.md/snippets) como mecanismo
de personalização. Ative **Configurações → Geral → Command line interface** para
usar a [CLI oficial](https://help.obsidian.md/cli). Ela precisa do aplicativo aberto.

O exemplo abaixo cria somente `snippets/oraculo-project-labels.css` dentro da
pasta de configuração do vault selecionado, pela API pública `Vault.adapter`.
Não copia arquivos diretamente para o vault e recusa sobrescrever um snippet
existente. Execute com um único operador, sem edição concorrente desse snippet
(o par `exists`/`write` não é uma criação exclusiva atômica).

```bash
python3 - "$labels_dir/project-labels.css" "NOME_DO_VAULT" <<'PY'
import json
import pathlib
import subprocess
import sys

css = pathlib.Path(sys.argv[1]).read_text(encoding="utf-8")
vault = sys.argv[2]
assert css.startswith("/* Generated by oraculo obsidian project-labels.")
code = "(async () => {" + "const expected = " + json.dumps(vault) + ";"
code += "const css = " + json.dumps(css) + ";"
code += """
  if (app.vault.getName() !== expected) throw new Error('wrong_vault');
  const adapter = app.vault.adapter;
  const directory = app.vault.configDir + '/snippets';
  const path = directory + '/oraculo-project-labels.css';
  if (await adapter.exists(path)) throw new Error('snippet_exists');
  if (!(await adapter.exists(directory))) await adapter.mkdir(directory);
  await adapter.write(path, css);
  if (await adapter.read(path) !== css) throw new Error('snippet_write_mismatch');
  return {path, installed: true, activation: 'manual'};
})()
"""
subprocess.run(["obsidian", "vault=" + vault, "eval", "code=" + code], check=True)
PY
```

Confira o retorno `installed: true`; um erro do `eval` não é instalação confirmada.
Abra **Configurações → Aparência → Snippets CSS**, recarregue a lista e ative
`oraculo-project-labels`. A ativação usa a interface suportada; não edite
`appearance.json` nem chame métodos internos de gerenciamento de CSS.

Os métodos `configDir`, `getName`, `adapter.exists/mkdir/write/read/remove` estão
na [API oficial](https://github.com/obsidianmd/obsidian-api/blob/master/obsidian.d.ts).
O exemplo respeita uma pasta de configuração diferente de `.obsidian`.

## Atualizar ou remover

Uma mudança de título ou inclusão de projeto exige novo snapshot e regeneração
com os IDs desejados. O snippet é estático; não instala observador ou sincronização.
Primeiro desative o snippet na mesma tela de Aparência. Para remover somente o
arquivo gerado, execute pela CLI oficial, substituindo o nome do vault:

```bash
obsidian vault=NOME_DO_VAULT eval code="(async () => {
  const path = app.vault.configDir + '/snippets/oraculo-project-labels.css';
  const adapter = app.vault.adapter;
  if (!(await adapter.exists(path))) return {removed: false, reason: 'absent'};
  const css = await adapter.read(path);
  if (!css.startsWith('/* Generated by oraculo obsidian project-labels.'))
    throw new Error('not_generated_by_oraculo');
  await adapter.remove(path);
  return {path, removed: !(await adapter.exists(path))};
})()"
```

Confira `removed: true` (ou `reason: absent`) e recarregue a lista. Para atualizar,
instale o novo artefato pelo procedimento anterior e reative. Preserve o CSS
anterior fora do vault se quiser restaurar aquela apresentação. Desativar já
restabelece os rótulos originais; remover o arquivo é opcional.

## Verificação e limites

- Expanda `projects` e confira nome e UUID de cada projeto selecionado. Abra seus
  índices e links: os destinos devem continuar em `projects/<project_key>/...`.
- Confira que pastas não selecionadas, `shared`, `reviews` e subpastas não receberam
  prefixos. Desative/reative o snippet para conferir a reversibilidade.
- Em painel estreito, o Obsidian pode truncar a linha. Alargue o explorador para ver
  o identificador completo. Ordenação, busca, nomes acessíveis e dicas continuam
  sendo os do Obsidian; CSS não cria aliases de pasta ou novos destinos de busca.
- O seletor `.nav-folder-title[data-path] > .nav-folder-title-content` foi observado
  no Obsidian 1.14.4. Snippets são suportados, mas esses seletores do DOM não são
  uma API versionada. Atualizações ou temas podem exigir ajuste e novo teste visual.
  Se o seletor deixar de casar, o nome original permanece visível.
- O prefixo é omitido durante a edição inline (`contenteditable="true"`). Este
  recurso não habilita nem recomenda renomear pastas canônicas pelo Obsidian.
- Testes automatizados cobrem seleção, escaping, mapeamento canônico, atualização,
  falhas e CLI offline. A ativação e a inspeção visual no vault de destino são
  verificações separadas; gerar um arquivo não prova que ele está ativo.
